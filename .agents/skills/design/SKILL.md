# Professional Web Design Skill

Use this skill whenever designing, redesigning, or visually improving a website, page, component, or user interface.

## Core Principle

Do not make a website merely "look cool".

Design for:

- clarity
- hierarchy
- usability
- consistency
- responsiveness
- accessibility
- performance
- brand identity

The final result should feel intentionally designed rather than AI-generated.

## 1. Inspect Before Designing

Before changing the UI:

- inspect existing components
- inspect global styles
- inspect typography
- inspect colors
- inspect spacing
- inspect layout structure
- inspect existing design patterns
- understand the purpose of the page

Reuse good existing patterns instead of unnecessarily rebuilding everything.

## 2. Visual Hierarchy

Evaluate:

- primary action
- secondary actions
- headings
- supporting text
- navigation
- content sections
- whitespace
- visual weight

The user should immediately understand:

1. What this page is.
2. What matters most.
3. What they can do next.

## 3. Typography

Use a deliberate typographic system.

Consider:

- font family
- font size
- font weight
- line height
- letter spacing
- heading hierarchy
- paragraph readability

Avoid excessive font styles.

## 4. Layout

Use consistent:

- spacing
- grids
- alignment
- container widths
- section rhythm
- component proportions

Prefer responsive layouts over fixed desktop layouts.

## 5. Responsive Design

Always consider:

- desktop
- laptop
- tablet
- mobile

Check for:

- overflowing elements
- unreadable text
- broken navigation
- oversized components
- awkward spacing
- horizontal scrolling
- touch targets

## 6. Interaction Design

Consider appropriate:

- hover states
- focus states
- active states
- loading states
- empty states
- error states
- disabled states
- transitions
- animations

Animations should communicate state or improve the experience.

Do not add animation merely because it is possible.

## 7. Accessibility

Check:

- semantic HTML
- keyboard navigation
- focus visibility
- color contrast
- alt text
- labels
- accessible buttons
- screen-reader considerations
- reduced-motion behavior where appropriate

Accessibility is part of the implementation, not an afterthought.

## 8. Modern Design

Use modern design principles without blindly following trends.

Avoid:

- excessive gradients
- excessive glassmorphism
- excessive rounded cards
- random floating elements
- unnecessary animations
- decorative elements with no purpose
- generic AI dashboard aesthetics

Visual effects should support the product.

## 9. Performance

Do not sacrifice performance for appearance.

Consider:

- image optimization
- lazy loading
- animation cost
- unnecessary client components
- bundle size
- unnecessary JavaScript
- layout shifts
- font loading

## 10. Browser Verification

For meaningful UI changes:

1. Run the application.
2. Open the relevant page in the browser.
3. Inspect the actual result.
4. Check desktop behavior.
5. Check mobile behavior.
6. Look for visual bugs.
7. Fix problems.
8. Re-check.

Do not declare a design complete from source code alone.

## 11. Design Quality Test

Before finishing, ask:

- Does the hierarchy make sense?
- Is the page visually balanced?
- Is the spacing consistent?
- Is typography readable?
- Is the interface responsive?
- Are interactions obvious?
- Are animations purposeful?
- Is the design accessible?
- Does it feel coherent with the rest of the project?
- Does anything look like unnecessary AI-generated decoration?

Fix obvious problems before reporting completion.

## Final Report

Report:

### Design Changes
What changed visually.

### UX Changes
What changed in interaction or usability.

### Responsive Verification
What screen sizes were checked.

### Performance
Any meaningful performance considerations.

### Remaining Issues
Anything that still needs attention.
